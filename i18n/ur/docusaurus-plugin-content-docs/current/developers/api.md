Rent Party API ایک REST API ہے جس کا ایک ہی بنیادی پتہ ہے۔ یہ آپ کے اپنے ریکارڈ پڑھتی ہے، اور آپ کی اجازت ہونے پر محفوظ شدہ کھیل ہٹا سکتی ہے۔ ہر راستے اور فیلڈ کی تفصیل OpenAPI فائل میں ہے؛ وہی مستند حوالہ ہے۔ اس صفحے میں پتہ اور فہرستوں کے مشترک اصول ہیں۔

## بنیادی پتہ کیا ہے؟ {#base-address}

```text
https://bgajltrjcqnchwhewouc.supabase.co/functions/v1/api/v1
```

آخر میں `v1` API کا ورژن ہے۔ ہر درخواست کے لیے ٹوکن یا منسلک ایپ چاہیے۔ [رسائی ٹوکن](./authentication.md) دیکھیں۔

```bash
curl -H "Authorization: Bearer $RENTPARTY_TOKEN" \
  https://bgajltrjcqnchwhewouc.supabase.co/functions/v1/api/v1/openapi.json
```

## کیا پڑھا جا سکتا ہے؟ {#resources}

| آپ کے ریکارڈ کا حصہ | پڑھنا | ہٹانا |
|---|---|---|
| پروفائل اور اعداد و شمار | ہاں | نہیں |
| ختم شدہ کھیلوں کے نتائج | ہاں | نہیں |
| بیجز اور ریٹنگ کی تاریخ | ہاں | نہیں |
| محفوظ شدہ کھیل | ہاں | ہاں، ہٹانے کی اجازت کے ساتھ |

جو کھیل ابھی جاری ہے وہ API میں نہیں ملتا، اور API سے کسی چال، نتیجے یا ریٹنگ کو بدلا نہیں جا سکتا۔ نتائج میں صرف وہی چیزیں آتی ہیں جو کھیل ختم ہونے پر میز نے دیکھی تھیں، کسی دوسرے کھلاڑی کی نجی تفصیل نہیں۔

## پوری تفصیل کہاں ہے؟ {#reference}

| فائل | پتہ | کس سے کھولیں |
|---|---|---|
| OpenAPI 3.1، JSON | [`/v1/openapi.json`](https://bgajltrjcqnchwhewouc.supabase.co/functions/v1/api/v1/openapi.json) | کوئی بھی OpenAPI ٹول: Swagger UI، Redocly، Postman، Insomnia یا کلائنٹ جنریٹر |
| یہی فائل Markdown میں | [`/v1/openapi.md`](https://bgajltrjcqnchwhewouc.supabase.co/functions/v1/api/v1/openapi.md) | براؤزر، ٹیکسٹ ایڈیٹر یا ایسا AI اسسٹنٹ جس میں آپ اسے خود پیسٹ کریں |

دونوں فائلیں API کے اسی ماخذ سے بنتی ہیں؛ اس لیے کوئی غیر موجود راستہ درج نہیں ہوتا اور موجود راستہ چھوٹتا نہیں۔

API، MCP اور ویب ہکس کے موجودہ ورژن کی تاریخ [ڈیولپر تبدیلیوں کے ریکارڈ](./changelog.md) میں ہے۔ ہر راستے کی تفصیل کے لیے OpenAPI فائل دیکھیں۔

اگر آپ کے کوڈ کو بار بار API پڑھنے کے بجائے کھیل ختم ہونے پر اطلاع چاہیے تو [ویب ہکس](./webhooks.md) دستخط شدہ ترسیل اور دوبارہ کوششوں کی تفصیل دیتے ہیں۔

فائل کے چار حصے زیادہ تر سوالوں کے جواب دیتے ہیں:

- **`paths`:** ہر راستہ، اس کا طریقہ اور مطلوبہ اجازت۔
- **`components.schemas`:** جواب میں آنے والی ہر فیلڈ اور اس کی قسم۔ جو فیلڈ یہاں نہیں، وہ بھیجی نہیں جاتی۔
- **`components.securitySchemes`:** داخلے کے دو طریقے، bearer ٹوکن اور OAuth۔
- **خرابی کے جوابات:** ہر `code` جو [خرابی کی ساخت](./authentication.md#errors) میں آ سکتا ہے، راستہ بہ راستہ۔

## فہرست کے صفحات کیسے کام کرتے ہیں؟ {#pagination}

ہر فہرست صفحات میں آتی ہے:

- عام طور پر **ہر صفحے پر 20 قطاریں**، زیادہ سے زیادہ **50**۔
- مزید اندراجات ہوں تو جواب میں `next_cursor` ملتا ہے۔ اگلا صفحہ منگوانے کے لیے یہی قدر واپس بھیجیں۔
- `next_cursor` نہ ہو تو وہ آخری صفحہ ہے۔

کرسر صفحہ نمبر نہیں، ایک نشانی ہے۔ آپ کا کوڈ نتائج پڑھ رہا ہو اور اس دوران کوئی کھیل ختم ہو جائے تو پہلے سے پڑھے گئے نتائج کی جگہ نہیں بدلتی۔ ہر فہرست کے راستے میں صفحے کے سائز اور کرسر کے پیرامیٹر OpenAPI فائل میں درج ہیں۔

## حدوں اور خرابیوں کا کیا ہوگا؟ {#limits-and-errors}

یہ ہر راستے پر ایک جیسی ہیں اور [رسائی ٹوکن](./authentication.md#rate-limits) کے صفحے پر درج ہیں۔
