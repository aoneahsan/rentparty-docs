Rent Party API एक पते पर उपलब्ध REST API है। यह आपके अपने रिकॉर्ड पढ़ता है और आपकी अनुमति होने पर सेव किया खेल हटा सकता है। हर रूट और फ़ील्ड OpenAPI फ़ाइल में दर्ज है; वही पूरा संदर्भ है। यह पेज उसका पता और सभी सूचियों के नियम बताता है।

## मूल पता क्या है? {#base-address}

```text
https://bgajltrjcqnchwhewouc.supabase.co/functions/v1/api/v1
```

आखिर का `v1` API का संस्करण है। हर अनुरोध के लिए टोकन या जुड़ा ऐप चाहिए। [एक्सेस टोकन](./authentication.md) देखें।

```bash
curl -H "Authorization: Bearer $RENTPARTY_TOKEN" \
  https://bgajltrjcqnchwhewouc.supabase.co/functions/v1/api/v1/openapi.json
```

## आप क्या पढ़ सकते हैं? {#resources}

| आपके रिकॉर्ड का हिस्सा | पढ़ सकते हैं | हटा सकते हैं |
|---|---|---|
| प्रोफ़ाइल और आँकड़े | हाँ | नहीं |
| पूरे हो चुके खेलों के नतीजे | हाँ | नहीं |
| बैज और रेटिंग का इतिहास | हाँ | नहीं |
| सेव किए हुए खेल | हाँ | हाँ, हटाने की अनुमति के साथ |

चल रहा खेल API में नहीं मिलता। API से उसकी चाल, नतीजा या रेटिंग बदली नहीं जा सकती। नतीजों में खेल खत्म होने पर मेज़ पर दिखी जानकारी होती है, दूसरे खिलाड़ी का निजी विवरण नहीं।

## पूरा संदर्भ कहाँ है? {#reference}

| फ़ाइल | पता | किससे खोलें |
|---|---|---|
| OpenAPI 3.1, JSON | [`/v1/openapi.json`](https://bgajltrjcqnchwhewouc.supabase.co/functions/v1/api/v1/openapi.json) | Swagger UI, Redocly, Postman, Insomnia या क्लाइंट जनरेटर जैसे किसी भी OpenAPI टूल से |
| वही संदर्भ, Markdown में | [`/v1/openapi.md`](https://bgajltrjcqnchwhewouc.supabase.co/functions/v1/api/v1/openapi.md) | ब्राउज़र, टेक्स्ट एडिटर या किसी AI सहायक में पेस्ट करके |

दोनों फ़ाइलें API के उसी स्रोत से बनती हैं। इसलिए वे किसी गैर-मौजूद रूट को नहीं दिखातीं और किसी मौजूदा रूट को नहीं छोड़तीं।

वर्तमान API, MCP और वेबहुक कब जोड़े गए, यह [डेवलपर बदलाव सूची](./changelog.md) में देखें। हर रूट का विवरण OpenAPI फ़ाइल में ही है।

अगर आपके कोड को बार-बार API पढ़ने के बजाय खेल पूरा होने पर इवेंट चाहिए, तो [वेबहुक](./webhooks.md) में हस्ताक्षरित डिलीवरी और दोबारा कोशिश के नियम देखें।

फ़ाइल के ये चार हिस्से अधिकतर सवालों के जवाब देते हैं:

- **`paths`**: हर रूट, उसका मेथड और ज़रूरी अनुमति।
- **`components.schemas`**: जवाब में आने वाला हर फ़ील्ड और उसका प्रकार। जो फ़ील्ड मौजूद नहीं है, वह भेजा नहीं जाता।
- **`components.securitySchemes`**: प्रवेश के दो तरीके, बेयरर टोकन और OAuth।
- **त्रुटि जवाब**: हर रूट के लिए [त्रुटि प्रारूप](./authentication.md#errors) में आने वाला हर `code`।

## पेजिनेशन कैसे काम करता है? {#pagination}

हर सूची पेजों में आती है:

- डिफ़ॉल्ट रूप से **20 पंक्तियाँ प्रति पेज**, अधिकतम **50**।
- और रिकॉर्ड होने पर जवाब में `next_cursor` आता है। अगले पेज के लिए वही मान वापस भेजें।
- `next_cursor` न हो तो वह आखिरी पेज है।

कर्सर पेज नंबर नहीं, एक निशान है। आपकी स्क्रिप्ट नतीजों के बीच पहुँची हो और तभी कोई खेल पूरा हो जाए, तो रिकॉर्ड एक स्थान नहीं खिसकते। हर सूची रूट के पेज आकार और कर्सर पैरामीटर OpenAPI फ़ाइल में लिखे हैं।

## सीमाएँ और त्रुटियाँ कहाँ मिलेंगी? {#limits-and-errors}

वे हर रूट पर एक जैसी हैं और [एक्सेस टोकन](./authentication.md#rate-limits) पेज पर दी गई हैं।
