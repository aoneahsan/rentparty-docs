У REST API Rent Party один базовый адрес. Через него можно читать собственные записи и, если вы разрешили, удалять сохранённые партии. Все маршруты и поля описаны в файле OpenAPI — это основной справочник. Здесь указано, где его найти и как устроены списки.

## Какой базовый адрес? {#base-address}

```text
https://bgajltrjcqnchwhewouc.supabase.co/functions/v1/api/v1
```

`v1` в конце — версия API. Для каждого запроса нужен токен или подключённое приложение. См. [токены доступа](./authentication.md).

```bash
curl -H "Authorization: Bearer $RENTPARTY_TOKEN" \
  https://bgajltrjcqnchwhewouc.supabase.co/functions/v1/api/v1/openapi.json
```

## Какие данные можно читать? {#resources}

| Часть вашей записи | Читать | Удалять |
|---|---|---|
| Профиль и статистика | Да | Нет |
| Результаты завершённых партий | Да | Нет |
| Значки и история рейтинга | Да | Нет |
| Сохранённые партии | Да | Да, с отдельным разрешением на удаление |

Партия, которая ещё идёт, недоступна через API. API не позволяет изменить ход, результат или рейтинг. Результаты отражают итог партии и не раскрывают закрытые данные других игроков.

## Где находится полный справочник? {#reference}

| Файл | Адрес | Чем открыть |
|---|---|---|
| OpenAPI 3.1, JSON | [`/v1/openapi.json`](https://bgajltrjcqnchwhewouc.supabase.co/functions/v1/api/v1/openapi.json) | Swagger UI, Redocly, Postman, Insomnia или другой инструмент OpenAPI |
| Те же сведения в Markdown | [`/v1/openapi.md`](https://bgajltrjcqnchwhewouc.supabase.co/functions/v1/api/v1/openapi.md) | Браузер, текстовый редактор или ИИ-помощник, которому вы передадите файл |

Оба файла создаются из того же источника, что и API: они не должны перечислять несуществующие маршруты или пропускать действующие.

В [журнале изменений для разработчиков](./changelog.md) указано, когда появились текущие API, MCP и вебхуки. Подробности каждого маршрута остаются в файле OpenAPI.

Если вашему коду нужно событие о завершении партии вместо очередного чтения API, [вебхуки](./webhooks.md) поддерживают подписанную доставку и повторные попытки.

В файле чаще всего нужны четыре раздела:

- **`paths`** — маршруты, методы и требуемые разрешения.
- **`components.schemas`** — возможные поля ответа и их типы. Отсутствующее в схеме поле не передаётся.
- **`components.securitySchemes`** — два способа входа: bearer-токен и OAuth.
- **Ответы с ошибками** — значения `code` в [формате ошибки](./authentication.md#errors) для каждого маршрута.

## Как работает постраничная выдача? {#pagination}

Каждый список выдаётся по страницам:

- По умолчанию **20 записей на страницу**, максимум **50**.
- Если после страницы есть ещё записи, ответ содержит `next_cursor`. Передайте его для получения следующей страницы.
- Если `next_cursor` отсутствует, это последняя страница.

Курсор — это закладка, а не номер страницы. Если во время чтения результатов закончится новая партия, записи не сдвинутся на одну позицию. Параметры размера страницы и курсора для каждого списка указаны в файле OpenAPI.
